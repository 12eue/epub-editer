# 2026-10-06

## 修复：切换页面视图时光标位置正确但永远显示第一页

承 2026-10-05 的标签页位置记忆修复，用户反馈"光标位置没错但切换后永远显示第一页"。通过 CDP 实机调试（electron `--remote-debugging-port` + Node 内置 WebSocket 驱动，脚本在 /tmp/es-test/）定位到**两个独立 bug**：

### Bug 1：预览模式捕获到过期的锚点偏移（app.mjs）
`captureCurrentViewLocation` 的 `frameViewAnchor` 快捷分支只检查"选区节点/偏移是否等于锚点"，但**用户滚动不会改变选区**——于是选中匹配锚点时就复用旧的 `sourceOffset`（通常是章节开头 215），而 percent 是实时算的正确值。restore 优先用 offset → 永远滚回顶部。`currentFramePoint` 对预览模式也是无条件信任选区，同样 stale。

**修复**：新增 `caretRectInFrame` / `caretVisibleInFrame` 辅助函数（约 1554 行），两处都要求**选区光标在视口内**才信任选区/锚点，否则落到 `firstVisibleFrameTextPoint`（取视口首个可见文本点）。阅读模式原本就有 scrollTop 差值检查，未受影响。

### Bug 2：Chromium `focus()` 自动滚动摧毁显式滚动（code-editor.mjs）
`scrollToOffset` 原顺序：设 scrollTop → `focus()` → `setSelectionRange()`。实测（scrollTop setter 陷阱 + 微测试证实）：**textarea 被 focus 时 Chromium 会同步滚动内部滚动条以显示"当前选区"**，而新编辑器选区还在 (0,0)，于是滚动立刻被打回 0——JS 层面无任何写入，纯引擎行为。这正是"光标对（setSelectionRange 生效）但显示第一页"。

**修复**：`scrollToOffset` 改为 先 `setSelectionRange` → `focus({ preventScroll: true })` → 再设 scrollTop/scrollLeft → `syncScroll()`。`setSelection` 改为 先设选区后聚焦（保留聚焦时滚动到光标的原行为，只是消除了顺序错位），不用 preventScroll。

### 验证
实机四组用例全 PASS：A 预览切标签页（60%→59%）；B HTML 光标 80%→预览落位 81%；C 预览 50%→HTML 光标 48% 且滚动落位 49%；D 阅读↔预览往返保持 55%。`node --check` 通过，单元测试 10/10。
