# 2026-10-05

## 修复：标签页切换时跳回第一行

**问题**：在多个文档标签页之间切换时，视图总是跳转到文档开头（第一行），而不是该标签页上次浏览的位置。

**根因**（`src/renderer/app.mjs` 的 `openResource()`）：
1. 切换前执行 `pendingViewLocation = null`，丢弃了位置信息；
2. `state.pendingReveal = options` 在默认空参数时是 `{}`，空对象为 truthy，导致 `restoreViewLocation()` 第一行判断 `state.pendingReveal` 时直接 `return false`，还原逻辑被永久屏蔽；`revealPending()` 对空对象也不做任何滚动。

**修复方案**：新增按资源路径记忆浏览位置的 `resourceViewLocations` Map（key 经 `normalizePath` 归一化），配套 `rememberViewLocationForPath` / `recallViewLocationForPath` / `forgetViewLocationForPath` 三个辅助函数（位置约 1643 行）：
- `openResource()`：切换走前 `remember` 旧路径，无显式定位参数（offset/hash/percent）时 `recall` 目标路径并赋给 `pendingViewLocation`；`state.pendingReveal` 仅在 options 非空时设置；
- `setMode()`：模式切换时同步刷新记忆表；
- `closeResourceTab()`：删除被关标签的记忆，切到相邻标签时恢复其位置；
- `navigateSpine()`（上一节/下一节）改为显式传 `{ percent: 0 }`，保留"跳到章节开头"的原行为；
- 删除/清理图片、删除资源时清理记忆并恢复新激活标签的位置；重命名资源时把记忆转移到新路径；
- `loadBook()` / `createBook()` / `closeBook()` 清空记忆表。

位置数据的坐标系三种模式通用：`captureCurrentViewLocation` 返回 `{path, offset, percent}`，offset 均为整份源码文本偏移；代码编辑器直接 `scrollToOffset`，iframe 经 `sourceBodyTextMap`/`frameTextMap` 做文本索引映射。

验证：`node --check` 语法通过，`node --test test/*.test.mjs` 10/10 通过。项目无 git 仓库。
